# 初回規範ヒアリング設計（interview）

SKILL.md「Phase 2 › 初回規範ヒアリング」の詳細編。質問の設計と、回答をルート AGENTS.md の「運用前提」節（[templates.md](templates.md)）へ書き下す規律を定める。実施条件の正本は SKILL.md の表（初回と `--interview` のみ。Gate と同一バッチ）。

## スキップ規律

質問の前に Phase 1 の探索結果と照合し、**導出できた項目は質問しない**。質問する項目も白紙で訊かず、推定値と根拠を提示して確認・訂正を求める形にする（回答の手間を最小化する）。

## 質問セット（最大4問）

| # | 項目 | 形式 | 質問前の導出 |
|---|---|---|---|
| 1 | プロジェクトの目的（何を達成するためのものか。1-2文） | 自由記述。推定候補を提示 | README・パッケージ定義・LP |
| 2 | 開発フェーズ | 3値の選択式。推定値を推奨として提示 | 下記ヒューリスティクス |
| 3 | ブランチ・リリース運用 | 検出結果の確認 | 下記の検出。自明なら質問自体を省く |
| 4 | エージェントへの特記制約（破壊的変更の可否・触ってはならない領域・未リリース機能の扱い等） | 自由記述（任意） | 導出不能。常に訊いてよい |

コーディング規約・テスト方針・Git 規約・セキュリティ設定は**質問しない**。コードベースから導出する領域であり、Phase 1 の観点別探索が担当する。導出できなければ書かない（推測で埋めない）。

## 開発フェーズの3値語彙

変数形式（`DEVELOPMENT_PHASE: 値` 等）では書かず、「運用前提」節に**自然文**で書く。語彙は次の3値に固定する:

| 値 | 意味 | 行動への含意（この1文を添えて書く） |
|---|---|---|
| 安定運用 | 本番稼働中。バグ修正と段階的改善が主 | 破壊的変更は原則禁止 |
| 両者 | 安定運用と新規開発が混在 | 新機能は慎重に、既存機能は保守的に |
| ビルドアンドスクラップ | 未リリース・技術検証・初期開発 | 破壊的変更と後方互換の切り捨てを許容 |

記述例: 「本プロジェクトはビルドアンドスクラップ段階である。破壊的変更を許容し、後方互換は明示的に求められない限り考慮しない。」

推定ヒューリスティクス（推奨値の提示に使う。確定には使わない）:

- リリースタグ・CHANGELOG・semantic-release 等のリリース機構あり → 安定運用寄り
- version 0.x・リリースタグ無し → ビルドアンドスクラップ寄り
- production 環境への deploy workflow あり → 安定運用 or 両者

## ブランチ・リリース運用の検出

```bash
git remote show origin 2>/dev/null | grep 'HEAD branch'   # 既定ブランチ
git branch -r                                             # 恒常ブランチ（develop / staging / release 等）の有無
ls .github/workflows/ 2>/dev/null                         # deploy 系 workflow の有無
```

- 既定ブランチ1本の運用なら書かない・訊かない（自明な事実は AGENTS.md に書かない）。
- 非自明な構成（develop/main の2段、release ブランチ、main 直 push 運用等）だけを「運用前提」節に書く。

## 書き下し規律

- 回答は要約しすぎず水増しもせず、**行動規範として1〜3文**で「運用前提」節に書く。
- 未回答・スキップされた項目は書かない。「承認不要」実行で訊けなかった導出不能項目は〔要確認: 初回ヒアリング未実施〕を残す。
