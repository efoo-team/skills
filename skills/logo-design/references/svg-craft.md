## 1. 描き方

### 座標系と SVG の入力仕様

アプリアイコン（`icon.svg`）は、`viewBox="0 0 1024 1024"` の、角丸なしで四隅まで塗った正方形にする。アイコン背景は `id="background"`、シンボルマークは `<g id="symbol">` に入れる。角丸は、ホーム画面やストアが後から付ける。スクリプト（`home-screen.mjs` など）はこの入力仕様を検査し、仕様から外れた SVG は、対処つきのエラーで止まる。

`symbol.svg` と `symbol-dark.svg` の `viewBox` は、シンボルマークの外接矩形に合わせて切る。正方形でなくてよい。余白は付けない。外接矩形は、`export-png.mjs` で `--bg none` の PNG に書き出し、アルファが 0 でないピクセルの範囲から求める（幾何ライブラリで面を作った場合は、ライブラリの bounds を使う）。余白は、サイトのヘッダーなどの表示場面の側が付ける。1024 角の余白つきで書き出すと、表示場面の中でシンボルマークが小さく表示される。

角度で図形を組むときは、真上を 0、時計回りを正とする。SVG の y 軸は下向きなので、nonzero の塗りの規則では穴の向きを外周と逆にし、evenodd では向きを問わない。いずれでも穴が抜けることを確認する。

### ブランドのシンボルマークとして描く

細い線の UI アイコンとしてではなく、面と比率と色を丁寧に設計したブランドのシンボルマークとして描く。細い線のシンボルマークは、小さいサイズで、歯車・チェックマーク・矢印・ハンバーガーメニューなどの汎用の UI アイコンに見えて、不採用になりやすい。

面は、円・楕円・カプセル・角丸の長方形・扇形・ストライプ状の細長い図形の和集合と差集合で組める。幾何ライブラリ（shapely など）で作った面は折れ線になるので、工程 5 の修正で曲線に直す（§2）。重なって色が濃くなる半透明の部分は、`fill-opacity` で表せる。重なりの継ぎ目は、工程 5 の修正で確認する。

### 角丸と曲線

円弧で角を丸めると、直線と円弧の接続で曲率が不連続になる。見た目の滑らかさを第一にする場面では、曲率が連続する（G2）丸めを使う。アイコン背景の切り抜きは、Figma の corner smoothing 60%・半径を 1 辺の 22.37% とする、曲率が連続する角丸（superellipse に近い形）で確認する。スクリプトのホーム画面のモックアップは、この形で切り抜く。

シンボルマークの角を丸めるときも、円弧による近似を最終品質とみなさない。角の手前から曲がり始めて、滑らかに続いているかを、目で確かめる。既製の字形や折れ線をそのまま使わない。字形を使う案は、曲線を引き直して、太さの変化と接続を設計する。

## 2. 制作品質の修正

選定案の見た目を変えずに、制作品質だけを上げる。直したら、`before-after.mjs` で修正前後を並べた画像を生成して残す。見た目が変わる修正は、利用者に示してから行う。

| 項目 | 確認と直し方 |
|---|---|
| favicon の簡略版 | 小さいサイズ（32 px と 16 px）で切れ目や細い溝が潰れる案は、切れ目を太くするか省いた `favicon.svg` を作る。暗いタブで見えにくいなら、アイコン背景を付けたアプリアイコン型の favicon にする |
| pixel grid への整列 | 16 px と 32 px の favicon で、縦横の端がピクセル境界に乗るように寸法を調整する。`--scenes pixel-zoom`（実ピクセルの拡大）で目で確かめる |
| 画面の背景が白い場合と暗い場合の輪郭 | 明るいアイコン背景が白い画面の背景と同化して輪郭が見えなくならないか、暗い画面の背景でシンボルマークが見えにくくならないかを確かめる。見えなくなるなら、方針の表の陰影の有無に従って直す。フラットなら、縁の色を追加するか、アイコン背景の明度を調整する。陰影を許す方針なら、淡いグラデーションにしてもよい |
| 光学的な中心と余白 | 幾何学的な中心ではなく、見た目の重心に置く。三角形は重心に置く。円は、同じ大きさの四角形より小さく見えるので、少し大きくする（オーバーシュート）。アイコン背景の中のシンボルマークの大きさと余白は、参考ロゴの隣に置いて決める |
| 折れ線から曲線へ | 幾何ライブラリが出力した折れ線は、3 次ベジェ曲線に直す。折れ線は輪郭が粗く、ファイルも大きくなる |
| 重なりの継ぎ目 | 隣り合う面の境目に、アンチエイリアスによる細い隙間（継ぎ目）が出ないかを、拡大して見る。出るなら、面を少し重ねるか、和集合にする |

ファイルサイズを削るだけの、見た目を変えない最適化（path の座標の桁を削る、メタデータを削除するなど）はしない。品質に効かないためである。ただし、折れ線の曲線化は、品質のために行う。

## 3. 書き出すもの

選定案について、次を書き出す。必要な大きさは、事実として集めたもの（ロゴを表示する画面と大きさ、アイコンを載せる先が定める大きさと形式）に合わせる。

| 書き出すもの | 内容 |
|---|---|
| シンボルマークの SVG | 明るい背景用（`symbol.svg`）と暗い背景用（`symbol-dark.svg`） |
| アプリアイコン | `icon.svg`（1024×1024、四隅まで塗った正方形）と、必要な大きさの PNG。角丸は付けない。大きさ・形式・容量の上限は、アイコンを載せる先（ストアなど）が定める値に合わせる |
| favicon | 簡略版の SVG と、必要な大きさの PNG |
| ロックアップ | シンボルマークとロゴタイプを並べた SVG（明るい背景用・暗い背景用）。ロゴタイプの文字は、外形の path にする（§4） |

PNG は `scripts/export-png.mjs` で、SVG からピクセル単位で書き出す。書き出した後、白い画面の背景と暗い画面の背景に置いた画像を生成して、目で確かめる。

書き出したファイルは、プロジェクトの既存のアセット置き場に置く。置き場所が決まっていなければ、利用者に尋ねる。

## 4. 書体のライセンスと outline 化

ロックアップのロゴタイプの書体は、OFL（SIL Open Font License）などのライセンスが許すものにする。文字は `scripts/text2path/` で、outline の path にする。Web フォントに依存しないためである。書体名・ウェイト・ライセンスは、`designs.json` に記録する（例: 「plus-jakarta-sans wght 700（SIL OFL 1.1）」）。

ロックアップは、シンボルマークの高さを基準にして、ロゴタイプの大きさと縦位置を決める。ロゴタイプは、小文字の高さ（x-height）ではなく、大文字の高さ（cap height）を、シンボルマークの見た目の高さにそろえる。cap height をそろえた結果、ロゴタイプが支配的に見えるときは、ロゴタイプの cap height をシンボルマークの高さより小さくして、参考ロゴのロックアップの比率に合わせる。縦の中心は、シンボルマークの光学的な中心に合わせる。シンボルマークとロゴタイプの間隔は、シンボルマークの幅を目安にして、目で調整する。全体の `viewBox` は、シンボルマークとロゴタイプの外接矩形に合わせて切る。`text2path --format json` の `metrics` と `advance` から、cap height と文字列の幅が得られる。組んだら、明るい背景と暗い背景で、参考ロゴのロックアップの隣に置いて確かめる。
