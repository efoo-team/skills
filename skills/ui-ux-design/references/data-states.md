# データ状態チェックリスト（data-states）

SKILL.md 設計手順4（データ状態の網羅）で使う。対象 UI に表示・操作されるデータ（オブジェクト）ごとに、以下の全状態を設計対象にする。確立された単一の網羅チェックリストは既存体系に存在しないため、このファイルが正本である。

## 表示状態

- [ ] 空（初回・0件）: 放置された空白にせず、説明と次の一手（主アクション）を示す empty state にする
- [ ] ローディング: 応答時間の閾値（0.1秒/1秒/10秒）で表現を変える
- [ ] 1件〜少数: 一覧デザインが1件でも成立するか
- [ ] 大量: ページネーション/仮想化/検索・絞り込みの要否、既定ソート、表示上限
- [ ] エラー: 原因と次の一手を示す。トーストで流さない
- [ ] 権限なし: 権限上不可能なら hide、条件を満たせば可能なら disabled＋理由表示
- [ ] stress cases: 極端に長い文字列、名前・値の欠損、削除済み・無効化済みの参照先、境界日時

## 操作×状態マトリクス

主要操作（作成・閲覧・編集・削除・一括操作）ごとに:

- [ ] 実行前: その操作が可能/不可能であることと、不可能な理由が見えるか
- [ ] 実行中: 多重送信の防止、進行の可視化
- [ ] 成功: 結果がどこに反映されたか見えるか、Undo を提供できるか
- [ ] 失敗: 入力内容が保全されるか、リトライ経路があるか
- [ ] 部分的成功: 一括操作の一部失敗をどう表示・回復させるか
- [ ] 競合: 他ユーザーの同時変更・古いデータ上での操作をどう扱うか

## 記入様式

状態ごとに「見えるもの・押せるもの・次の一手」を1行で書く。設計しない状態を残す場合は「対象外」と理由を明記する（暗黙の未設計を残さない）。
