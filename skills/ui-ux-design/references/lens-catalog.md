## 1. 決定領域別レンズカタログ（12領域）

### 領域1: 入口と開示

- レンズ: Progressive Disclosure（Nielsen 2006。起源は Carroll & Carrithers の Training Wheels）、Staged Disclosure、Hick's Law、Krug の第二法則（mindless choices）、Microsoft の Inductive User Interface
- 境界条件: 開示は2段階以内（3段階以上は低 UX）。1つのメニュー・開示層のアクションは2〜6個。各段階のラベルが次の内容を予測させる「情報の匂い」の強さが、深さを増やす正当化条件（Larson & Czerwinski）。最頻アクションのデフォルトタブ化・前回選択の記憶・ショートカットで頻用者の効率（Nielsen ヒューリスティック #7）を担保する。Hide は Remove ではない（Colborne の4戦略）。

### 領域2: ナビゲーションとIA

- レンズ: OOUI（オブジェクト指向 UI。例外条件も原典が明記: 対象選択が不要な新規作成・自己完結の定型手続きはタスクベースを許容）、OOUX の ORCA プロセス、Information Foraging と情報の匂い、flat vs deep 階層、ファセット分類、タクソノミー≠ナビゲーションの区別
- 境界条件: ナビゲーションラベルに「管理」「その他」等の汎用語や汎用動詞を使わない。パンくずは深い階層のみ。ダッシュボードは運用系（今日やること）と分析系（傾向を見る）を混在させない。

### 領域3: 知覚と配置

- レンズ: ゲシュタルト原則（近接・類同・共通領域・連続・閉合）、視覚階層、前注意的属性、F字パターン（実証済み。Z字パターンは経験則）
- 境界条件: 強調は単一属性かつ希少に使う（全部強調は無強調）。余白のグルーピングで足りる所に罫線・枠を足さない。配置はグルーピングの宣言として読まれる（近くに置く＝関係があると宣言する）。

### 領域4: 操作の物理

- レンズ: Fitts's Law、ターゲットサイズ標準、サムゾーン（モバイルの親指到達域）、KLM-GOMS（操作ステップの定量比較）
- 境界条件: タッチターゲットは最低24px（WCAG 2.2）、推奨44pt（iOS）/ 48dp（Android）。hover にしか出ない操作を作らない（タッチデバイスで到達不能）。破壊的操作はあえて届きにくい位置・距離に置く。

### 領域5: 器の選択

- レンズ: モーダル適用基準、ウィザード適用条件、Tabs Used Right（NN/g）、通知階層（inline / toast / banner / modal の使い分け。IBM Carbon・Shopify Polaris の通知設計）
- 境界条件: モーダルは「短時間で自己完結する入力」か「重大な確認」のみ。タブは比較不要の同列内容のみ（比較が必要なら並置）。エラーをトーストで流さない（persistent な表示にする）。

### 領域6: フォーム

- レンズ: Luke Wroblewski『Web Form Design』（上置きラベル・1カラム）、インライン検証タイミングの reward early, punish late、選択式優先（自由入力より選択肢）
- 境界条件: まだエラーになっていない欄を入力中に叱らない。プレースホルダをラベルの代わりにしない。2〜3択はラジオボタンで見せる（ドロップダウンに畳まない）。

### 領域7: エラーと安全

- レンズ: スリップ/ミステイクの区別（Norman）、ポカヨケ・強制機能、確認よりも Undo 優先、意図的摩擦（microboundaries）
- 境界条件: 確認ダイアログを乱用しない（高頻度に出すと形骸化し、重大確認まで素通りされる）。type-to-confirm は不可逆操作のみ。摩擦の追加は高リスク操作に限定する。

### 領域8: フィードバックと時間

- レンズ: システム状態の可視性（Nielsen #1）、応答時間の閾値 0.1秒/1秒/10秒（Nielsen）、Doherty threshold（400ms）、楽観的 UI、empty states（NN/g）
- 境界条件: 10秒を超える処理はバックグラウンド化して進捗を可視化する。自動保存を採用してもドラフト状態の明示と明示的な確定操作を残す。スケルトンスクリーンは相反する実験結果があり万能としない。

### 領域9: 動線内の発見と投資

- レンズ: Fogg Behavior Model（B=MAP。トリガーは facilitator 型を使う）、Hooked モデルの Investment（Nir Eyal）、pull revelation（必要の瞬間に開示する）、moment of need
- 境界条件: 気づかせ方は pull 型でなければ逆効果。投資行動（テンプレート化・設定の作り込み）の押し付けは Nagging（ダークパターン）になる。

### 領域10: B2B・業務システム

- レンズ: UI 密度（情報の価値密度で決める）、一括操作の設計、組織設定と個人設定の分離、Hide vs Disable、永遠の中級者（Cooper）
- 境界条件: 高密度 UI は熟練ユーザー×高頻度画面のみ。権限上不可能な操作は hide、条件を満たせば可能な操作は disabled＋理由表示。既定の UI は初心者でも熟練者でもなく中級者に最適化する。

### 領域11: 言葉

- レンズ: 動詞＋目的語のボタンラベル（「保存する」ではなく「下書きを保存」）、front-loading（重要語を先頭に）、ユーザーの言語で語る（Nielsen #2）
- 境界条件: ナビゲーションは名詞・ボタンは動詞という分業を崩さない。同一概念の表記は用語集で固定する。

### 領域12: デフォルトと倫理

- レンズ: デフォルト効果・ナッジ、ダークパターン類型（Deceptive Patterns）、sludge（手続き妨害）、ブライトパターン
- 境界条件: デフォルト値は事業者都合ではなく利用者利益基準で決める。解約・退会は契約と同等の手数にする。偽の緊急性・事前選択済みの同意を使わない。

## 2. 確度管理表

根拠として引用する前にここを確認する。確度が「使わない」「引用しない」の主張を設計判断の根拠にしない。

| 主張 | 確度 | 扱い |
|---|---|---|
| F字パターン | NN/g の大規模実証（再検証あり） | 規則化してよい |
| Z字パターン | 経験則のみ（同水準の一次研究なし） | 参考にとどめる |
| ジャム実験（選択過多） | メタ分析で平均効果量ほぼゼロ | 根拠に使わない |
| Zeigarnik 記憶効果 | メタ分析で疑義 | 使わない（Ovsiankina の再開傾向は頑健で使用可） |
| スケルトンスクリーン | 相反する実験結果あり | 条件付き参考 |
| 「中断後23分で復帰」 | 一次資料で確認できず | 引用しない |
| 「action line」 | Fogg 原論文に存在しない俗称 | behavior activation threshold を使う |
| 「Nine States of Design」 | 一ブログ記事由来（Vince Speelman, Medium 2015）で学術的裏付けなし | 引用禁止（代替: NN/g empty states ＋ stress cases） |
| 「5ユーザーで十分」 | 定数の安定性に学術批判 | 形成的テストの目安にとどめる |
| ファーストクリック成功率の統計 | 二次資料一致・一次未到達 | 原則は使用可・数値は参考 |

## 3. 用語の正名（俗称を使わない）

- Fogg Behavior Model の閾値は **behavior activation threshold**（「action line」は原論文に存在しない俗称）。
- 中断課題の**再開傾向**は Ovsiankina 効果（頑健）。Zeigarnik の**記憶**効果とは別物であり、後者を根拠にしない。
- データ状態の網羅は **NN/g の empty states** と **『Design for Real Life』の stress cases** で語る（「Nine States of Design」は Vince Speelman の一記事＝Medium 2015 由来で、確立された体系ではないため根拠として使わない）。

## 4. 検証手法の位置づけ

- カードソート・ツリーテスト・ファーストクリックテストはユーザーのメンタルモデルを測る手法として価値が残る。位置づけは「実装前の必須ゲート」ではなく「実実装と並行して安価に回す確認」。
- ヒューリスティック評価は AI エージェントが安価に反復できる筆頭の検証手法。
- 構造仮説の検証は実 UI ＋ モックデータで行う（SKILL.md 原則0）。UI 生成が安価であることは出力が決定的に正しいことを意味しないため、生成した UI も上記の検証にかける。
